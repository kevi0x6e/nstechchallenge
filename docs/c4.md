
O worker **não tem relação com o PostgreSQL**. Essa ausência é a restrição central do desafio.

## Sequência — um batch (caminho feliz + falhas)

```mermaid
sequenceDiagram
  autonumber
  participant K as Kafka (partição)
  participant C as CdcConsumerService
  participant P as Projector
  participant V as Valkey (Lua)

  C->>K: Consume (até 2000 msgs / 20 ms)
  K-->>C: envelopes (+ tombstones ignorados)
  C->>P: ProjectAsync(batch)
  P->>P: map + LatestWins (max por veículo)
  P->>V: N × EVALSHA (pipelined, 1 RTT)
  V-->>P: 1 = aplicado / 0 = stale/duplicado
  P-->>C: ProjectionResult
  C->>K: StoreOffset (commit em background a cada 1s)
  Note over C,V: Valkey falha → retry do MESMO batch (backoff) — offset não avança
  Note over C,K: Crash antes do commit → redelivery → Lua devolve 0 (no-op)
```
